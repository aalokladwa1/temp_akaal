## 1. P4 Phase Overview

Phase P4 expands the AKAAL Database Migration Platform from core relational engines into universal, multi-database, heterogeneous storage, cloud data warehouse, NoSQL, event stream, and object store connectivity while strictly preserving all frozen P0–P3 runtime migration authorities.

Connectors in P4 serve as universal translators and adapters that plug into the authoritative AKAAL runtime pipeline:
```
AKAAL UI
   ↓
Tauri IPC Gateway
   ↓
EngineGateway
   ↓
AkaalSuperEngine / WorkflowEngine
   ↓
Authoritative P0–P3 Migration & CDC Authorities
   ↓
Universal Connector / Capability Layer (IUniversalConnector)
   ↓
Technology-Specific Adapters & Drivers
   ↓
Database / Warehouse / NoSQL / Stream / Object Storage / Cloud
```

### P4.1 — Universal Connector Contract, Enterprise Connectivity Inventory, Existing-Capability Forensic Audit & Connector Foundation

- **Universal Connector Taxonomy (`akaal/connectors/taxonomy.py`)**:
  - Defined 15 canonical technology families: `RELATIONAL_DATABASE`, `CLOUD_DATA_WAREHOUSE`, `DOCUMENT_DATABASE`, `WIDE_COLUMN_DATABASE`, `GRAPH_DATABASE`, `KEY_VALUE_STORE`, `SEARCH_ENGINE`, `STREAM_EVENT_PLATFORM`, `DISTRIBUTED_FILESYSTEM`, `OBJECT_STORAGE`, `FILE_DATASET`, `LAKEHOUSE_ANALYTICS`, `CLOUD_PROVIDER`, `CONTAINER_ORCHESTRATION`, `CONNECTIVITY_INFRASTRUCTURE`.

- **Universal Capability Manifest (`akaal/connectors/manifest.py`)**:
  - Machine-readable, versioned capability manifest establishing authoritative feature declarations.
  - Enforces strict **fail-closed** capability querying: `UNKNOWN != SUPPORTED`. Any unproven or undeclared capability returns `UNKNOWN_NOT_PROVEN` or `UNSUPPORTED`.

- **Canonical Connection Profile (`akaal/connectors/profile.py`)**:
  - Reusable endpoint descriptor with strict credential sanitization (`to_sanitized_dict()`).
  - Plaintext secrets are NEVER persisted in state stores, logs, telemetry, or DTOs.

- **Universal Base & Extension Contracts (`akaal/connectors/contracts/`)**:
  - Core lifecycle contract `IUniversalConnector` (connect, test_connection, health_check, disconnect, reconnect, classify_error, get_capability_extension).
  - Progressive capability extensions: `IDatabaseCapability`, `IDocumentCapability`, `IWarehouseCapability`, `IStreamingCapability`, `IObjectStorageCapability`, `IWideColumnCapability`, `IGraphCapability`, `IKeyValueCapability`, `ISearchCapability`, `ICloudProviderCapability`.

- **Semantic Compatibility & Safety Matrix (`akaal/connectors/compatibility.py`)**:
  - Evaluates cross-system migration viability, schema conversion requirements, and lossiness warnings.
  - Retains heterogeneous position comparison prohibitions (P3.8/P3.8.1 fail-closed protection).

- **Universal Connector Registry & Legacy Bridge (`akaal/connectors/registry.py`, `bridge.py`)**:
  - Thread-safe registry wrapping all 19 baseline systems.
  - Preserves 100% of P0–P3 authorities.

## 4. P4.2.1 Hostile Enterprise Relational Connector Fleet Acceptance Audit

- **Adversarial Attack Groups Executed**: 42 Attack Groups (A through AP) across 37 dedicated hostile tests in `tests/unit/connectors/test_p4_2_1_relational_connector_fleet_hostile_audit.py`.
- **Defects Discovered & Rectified**:
  1. **DEF-P421-01 (Severity: MEDIUM)**: `parse_source_position` in `akaal/cdc/domain/positions.py` lacked type validation and raised `AttributeError` instead of `ValueError` when supplied non-dictionary input. Rectified with strict `isinstance(data, dict)` check.
  2. **DEF-P421-02 (Severity: HIGH)**: Conflation of bulk migration checkpoint resume and CDC log-position resume. Rectified by introducing explicit `supports_bulk_checkpoint_resume` and `supports_cdc_position_resume` attributes in `UniversalCapabilityManifest` (`akaal/connectors/manifest.py`) and wiring them through `LegacyAdapterUniversalBridge` (`akaal/connectors/bridge.py`).
  3. **DEF-P421-03 (Severity: MEDIUM)**: `ConnectionProfile` lacked a formal `tags` initialization argument while referencing it in instance dictionaries, and missing property alias `profile_id`. Rectified in `akaal/connectors/profile.py`.
  4. **DEF-P421-04 (Severity: LOW)**: `SQLiteAdapter.get_row_count` raised operational errors on uninitialized mock connection tables instead of gracefully falling back to mock mode row count estimation. Rectified in `akaal/adapters/rdbms/sqlite_adapter.py`.
- **Checkpoint Semantics Formally Separated**:
  - `IBM Db2`: Bulk Checkpoint Resume = `SUPPORTED` (YES) | CDC Position Resume = `UNSUPPORTED` (NO).
  - `SQLite`: Bulk Checkpoint Resume = `SUPPORTED` (YES) | CDC Position Resume = `UNSUPPORTED` (NO).
  - `Oracle`, `PostgreSQL`, `MySQL`, `MariaDB`, `MSSQL`: Bulk Checkpoint Resume = `SUPPORTED` (YES) | CDC Position Resume = `SUPPORTED` (YES).

## 5. P4.3 Milestones & Deliverables — Cloud Data Warehouse & Lakehouse Connector Fleet

Phase **P4.3** implements and hardens the 4 primary cloud analytical systems: **Snowflake**, **Google BigQuery**, **Amazon Redshift**, and **Databricks / Delta Lake**.

### The 4 Cloud Warehouse & Lakehouse Connectors:

1. **Snowflake Data Cloud (`akaal/adapters/warehouse/snowflake_adapter.py`)**:
   - Implements `BaseAdapter` and `IWarehouseCapability`.
   - Virtual warehouse management, database/schema hierarchies, clustering key discovery (`get_clustering_metadata`), and view discovery.
   - Rich Snowflake datatype normalization: `NUMBER(p,s)`, `FLOAT`, `BOOLEAN`, `VARCHAR`, `BINARY`, `DATE`, `TIME`, `TIMESTAMP_NTZ`, `TIMESTAMP_LTZ`, `TIMESTAMP_TZ`, `VARIANT`, `OBJECT`, `ARRAY`, `GEOGRAPHY`.
   - High-throughput parallel ingestion via staged `COPY INTO <table> FROM @<stage>`.
   - High-speed extraction via `UNLOAD / COPY INTO @<stage> FROM <table>`.
   - Explicit multi-statement transaction primitives (`BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK`).
   - Read-only validation access (`get_row_count`, `compute_checksum`).

2. **Google Cloud BigQuery (`akaal/adapters/warehouse/bigquery_adapter.py`)**:
   - Implements `BaseAdapter` and `IWarehouseCapability`.
   - GCP Project & Dataset discovery, time-partitioned and clustered table metadata.
   - Deep nested schema discovery: `RECORD` / `STRUCT` (with subfields) and `ARRAY` (with `REPEATED` mode).
   - Datatype normalization: `INT64`, `NUMERIC`, `BIGNUMERIC`, `FLOAT64`, `BOOL`, `STRING`, `BYTES`, `DATE`, `TIME`, `DATETIME`, `TIMESTAMP`, `GEOGRAPHY`, `JSON`, `STRUCT`, `ARRAY`.
   - High-speed parallel ingest via `LoadJob` and Storage Write API simulation from GCS stage URIs with automatic retry and write disposition handling.
   - Read-only validation access (`get_row_count`, `compute_checksum`).

3. **Amazon Redshift (`akaal/adapters/warehouse/redshift_adapter.py`)**:
   - Implements `BaseAdapter` and `IWarehouseCapability`.
   - Provisioned cluster & Serverless workgroup support, schema discovery, table distribution styles (`KEY`, `EVEN`, `ALL`), distkeys, and sort keys (`COMPOUND`, `INTERLEAVED`).
   - Datatype normalization: `SMALLINT`, `INTEGER`, `BIGINT`, `DECIMAL`, `REAL`, `DOUBLE PRECISION`, `BOOLEAN`, `CHAR`, `VARCHAR`, `DATE`, `TIMESTAMP`, `TIMESTAMPTZ`, `SUPER`, `GEOMETRY`, `HLLSKETCH`.
   - S3 staged bulk ingestion via `COPY <table> FROM 's3://...' IAM_ROLE '...' FORMAT AS PARQUET/CSV`.
   - High-speed extraction via S3 `UNLOAD ('SELECT * FROM ...') TO 's3://...'`.
   - Diagnostic failure isolation and transaction support.

4. **Databricks Delta Lake (`akaal/adapters/warehouse/databricks_adapter.py`)**:
   - Implements `BaseAdapter` and `IWarehouseCapability` under `ConnectorFamily.LAKEHOUSE_ANALYTICS` with `SystemType.DATABRICKS`.
   - Unity Catalog three-level namespace discovery (`catalog.schema.table`), managed vs external Delta table discovery, liquid clustering, and partition specifications.
   - Delta Lake datatype normalization: `BYTE`, `SHORT`, `INT`, `LONG`, `FLOAT`, `DOUBLE`, `DECIMAL`, `STRING`, `BINARY`, `BOOLEAN`, `TIMESTAMP`, `TIMESTAMP_NTZ`, `DATE`, `ARRAY`, `MAP`, `STRUCT`.
   - Delta table snapshot history & commit version extraction (`get_table_version`).
   - High-speed parallel ingest via Delta `COPY INTO` and ACID transactional writes.

### Staged Transfer Architecture (`akaal/connectors/staging.py`)

- Introduced `StagedTransferCoordinator` and `StagedTransferDescriptor` composing warehouse and lakehouse adapters with cloud object storage staging (S3, GCS, Azure Blob).
- Generates collision-resistant, deterministic stage keys bound to migration ID, job ID, and run ID (`akaal-staging/<migration_id>/<job_id>/<table_name>/batch_<batch_id>.<ext>`).
- Enforces guaranteed deterministic stage cleanup post-load.
- Strictly redacts all KMS keys, credentials, and customer secrets from telemetry and descriptors.

### Native Warehouse & Lakehouse Position Models (`akaal/cdc/domain/positions.py`)

- **`DeltaTableVersionPosition`**: Tracks table snapshot commit version (`table_version: int`, `table_name: str`, `timestamp_ms`, `commit_id`). Monotonically ordered within the same Delta table; cross-table and cross-engine comparisons fail closed with `TypeError`.
- **`WarehouseQueryPosition`**: Tracks bounded analytical query execution (`engine: str`, `query_id: str`, `chunk_index: int`, `row_offset: int`). Monotonically ordered within the same query ID; cross-query and cross-engine comparisons fail closed with `TypeError`.
