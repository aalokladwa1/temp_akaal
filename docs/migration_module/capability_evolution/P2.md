- **MySQL `TINYINT(1)` Semantic Hardening**: Hardened `TINYINT(1)` to preserve `INTEGER(bits=8)` by default unless explicit boolean evidence (`is_boolean=True`) is provided in metadata.
- **Oracle Parameter Ambiguity & Negative Scale**: Fixed type parameter parsing regex (`r"\(([\d\s,\-]+)\)"`) to support Oracle negative scale (`NUMBER(5,-2)`).

- **Unsigned 64-Bit Range Overflow Protection**: Mapped MySQL `BIGINT UNSIGNED` to PostgreSQL `NUMERIC(20,0)` to avoid signed 64-bit integer overflow (`ConversionSafety.SAFE`).
- **Dynamic Plugin Extensibility**: Added `register_normalizer(engine, func)` and `register_emitter(engine, func)` on `CanonicalTypeRegistry`.

### P2.9 / P2.9.1 — Validation-Only Mode, Deep Reconciliation & Semantic Hardening
- **Validation-Only Execution Mode ([`reconciliation.py`](file:///a:/temp_akaal/akaal/validation/domain/reconciliation.py))**: Implemented `ValidationExecutionMode.VALIDATION_ONLY` for independent validation of pre-existing source and target databases without requiring AKAAL migration history.
- **Validation-Only Write Firewall (`ValidationOnlyWriteFirewall`)**: Enforces `ValidationWriteFirewallError` if target mutation operations (`INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `DDL`) are attempted during `VALIDATION_ONLY` mode.
- **Universal Deep Reconciliation Engine (`CanonicalReconciliationEngine`)**: Hierarchical progressive narrowing (`Table -> Merkle Root -> Chunk -> Key Range -> Row -> Column`). Pinpoints `MATCHED`, `SOURCE_ONLY`, `TARGET_ONLY`, `VALUE_MISMATCH`, `UNSUPPORTED`, `INDETERMINATE`, `ERROR` row classifications and pinpoints exact mismatched columns (`ColumnDifference`).
- **Injective Composite Key Identity**: Uses length-prefixed framed bytes `_canonical_key_sort_bytes()` for composite PK sorting to prevent boundary collisions.
- **Rejection of Nullable Unique Keys**: Nullable unique keys containing `None` values are safely rejected as `INDETERMINATE` rather than fabricating stable identity.
- **False Match Firewall Enforcement**: Driver serialization or query exceptions force `ERROR` status and NEVER `MATCHED`.
- **Raw Data Privacy Firewall**: Excludes raw customer values/passwords/LOBs from routine evidence objects and log payloads.
- **Plugin Extensibility Guarantee**: IBM DB2 (DB #5) trace proves adding DB #5 / DB #50 requires 0 core engine modifications.
