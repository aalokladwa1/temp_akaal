### P2.3.1 — Datatype Semantic Acceptance Audit & Hardening
- **MySQL `TINYINT(1)` Semantic Hardening**: Hardened `TINYINT(1)` to preserve `INTEGER(bits=8)` by default unless explicit boolean evidence (`is_boolean=True`) is provided in metadata.
- **Oracle Parameter Ambiguity & Negative Scale**: Fixed type parameter parsing regex (`r"\(([\d\s,\-]+)\)"`) to support Oracle negative scale (`NUMBER(5,-2)`).
- **MSSQL `ROWVERSION` / `TIMESTAMP` Hardening**: Verified `ROWVERSION` normalizes to `VARBINARY(length=8, extra={"mssql_rowversion": True})` and emits `ConversionSafety.VENDOR_SPECIFIC` with warning when targeting PostgreSQL `BYTEA`.
- **Unsigned 64-Bit Range Overflow Protection**: Mapped MySQL `BIGINT UNSIGNED` to PostgreSQL `NUMERIC(20,0)` to avoid signed 64-bit integer overflow (`ConversionSafety.SAFE`).
- **Dynamic Plugin Extensibility**: Added `register_normalizer(engine, func)` and `register_emitter(engine, func)` on `CanonicalTypeRegistry`.

### P2.8 / P2.8.1 — Canonical Validation Engine, Serialization & Merkle Integrity
- **Canonical Value Serializer ([`physical_validator.py`](file:///a:/temp_akaal/akaal/validation/domain/physical_validator.py))**: Implemented versioned canonical serialization format (`SERIALIZATION_VERSION = AKAAL-CANONICAL-V1`).
- **Unambiguous Type Framing & Normalization**: Format `[TYPE_CAT_LEN]:[TYPE_CAT]:[NULL_FLAG]:[VAL_BYTES_LEN]:[VAL_BYTES]`. Handles `NULL`, `Decimal` normalization (`100.00` == `100`), float special values (`NaN`, `+Inf`, `-Inf`), UTF-8 Unicode NFC normalization, Oracle empty string semantics (`""` -> `NULL`), tz-aware datetime to UTC ISO8601, UUID bytes, JSON deterministic key ordering (`sort_keys=True`), and exact binary hashing.

- **Framed Row Serialization & Merkle Tree**: Prevents field boundary concatenation collisions (`["ab", "c"]` != `["a", "bc"]`). Computes SHA-256 Merkle root trees.

### P2.12 — Enterprise Report Export, Portable Evidence Package & Certification Delivery
- **Canonical Report Export Service ([`export_service.py`](file:///a:/temp_akaal/akaal/reporting/engine/export_service.py))**: Centralized, database-agnostic export authority (`CanonicalReportExportService`) producing customer-deliverable artifacts from `CanonicalReport` and `CertificationArtifact`.
- **Supported Export Formats**:
  1. **Canonical Report JSON**: Deterministic UTF-8 `AKAAL-CANONICAL-V1` JSON format.
  2. **Canonical Certification JSON**: Deterministic `AKAAL-CANONICAL-V1` certification artifact.
  3. **Enterprise PDF Migration Evidence Dossier**: Backend-generated PDF %PDF-1.7 covering Cover, Executive Summary, Validation Summary, Reconciliation Summary, Schema & Risk Summary, Governance Summary, Certification Section, and Final Evidence Notice.
  4. **Enterprise PDF Certificate**: Concise 1-2 page certification PDF artifact.
  5. **AKAAL Evidence Package (.zip)**: Portable archive containing:
     ```text
     AKAAL-EVIDENCE-<report_id>.zip
         ├── report/
         │     ├── canonical-report.json
         │     └── migration-evidence-dossier.pdf
         ├── certification/
         │     ├── certification.json
         │     └── certification.pdf
         ├── evidence/
         │     └── manifest.json
         └── integrity/
               └── checksums.sha256
     ```
  6. **Package Verification Service**: `verify_evidence_package(zip_data_or_path)` auditing archive structure and SHA-256 artifact hashes, returning `VALID`, `INVALID`, `INCOMPLETE`, `UNSUPPORTED_VERSION`, `ERROR`.
- **Privacy & Secret Firewall**: Shared backend redaction sanitizes passwords, tokens, API keys, and connection strings into `[REDACTED_SECRET]`. Zero raw customer rows, raw LOBs, or raw SQL bodies exported.
- **Hash Integrity != Digital Signature Boundary**: PDF certificate explicitly states SHA-256 fingerprint proves evidence integrity and is NOT an X.509 digital signature (`DIGITAL_SIGNATURE_IMPLEMENTED = NO`).
