### P2.3.1 — Datatype Semantic Acceptance Audit & Hardening
- **MySQL `TINYINT(1)` Semantic Hardening**: Hardened `TINYINT(1)` to preserve `INTEGER(bits=8)` by default unless explicit boolean evidence (`is_boolean=True`) is provided in metadata, preventing false conversion of small integer counts into boolean values.
- **Oracle Parameter Ambiguity & Negative Scale**: Fixed type parameter parsing regex (`r"\(([\d\s,\-]+)\)"`) to support Oracle negative scale (`NUMBER(5,-2)`). Preserved ambiguous `NUMBER` without parameters as unconstrained DECIMAL.
- **MSSQL `ROWVERSION` / `TIMESTAMP` Hardening**: Verified `ROWVERSION` normalizes to `VARBINARY(length=8, extra={"mssql_rowversion": True})` and emits `ConversionSafety.VENDOR_SPECIFIC` with warning when targeting PostgreSQL `BYTEA`.
- **Unsigned 64-Bit Range Overflow Protection**: Mapped MySQL `BIGINT UNSIGNED` to PostgreSQL `NUMERIC(20,0)` to avoid signed 64-bit integer overflow (`ConversionSafety.SAFE`).
- **Dynamic Plugin Extensibility**: Added `register_normalizer(engine, func)` and `register_emitter(engine, func)` on `CanonicalTypeRegistry` to allow future databases (e.g. IBM DB2 or DB #50) to dynamically register normalizers/emitters without modifying core registry source code.
- **Deterministic Schema Fingerprints**: Verified SHA-256 schema structural fingerprints remain 100% deterministic across repeated runs with `CanonicalType` models.
